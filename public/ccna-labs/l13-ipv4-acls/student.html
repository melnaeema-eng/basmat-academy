١. أهداف التعلم والمتطلبات

  • تطبيق قواعد مرتبة واختبار السماح والمنع.
  • تمييز ACL قياسية تعتمد المصدر عن ممتدة تحدد الخدمة والوجهة.

الموضوع: 5.6 ACL configuration and verification

المتطلبات: IPv4 وCLI وأساسيات VLAN والتوجيه؛ راجع المختبرات السابقة المناسبة. للورش استخدم الأدوات المحددة أدناه.

ابدأ بملف مختبر جديد معزول. لم تُشغّل هذه الأوامر على Packet Tracer ضمن إعداد الحزمة.

٣. جدول العناوين والإعدادات

العنصرالقيمة
PC-A / PC-B192.168.10.10 / .11 /24; gateway .1
Server192.168.20.10/24; gateway 192.168.20.1
R1 Gi0/0 / Gi0/1192.168.10.1/24 / 192.168.20.1/24

الاختصار /24 يعني 255.255.255.0، و/30 يعني 255.255.255.252. أدخل عناوين PC من Desktop → IP Configuration، ولا تستخدم عنوان الشبكة أو البث. IPv6 /64 مستقل عن أقنعة IPv4.

٤. خطوات التنفيذ

  1. استخدم 2911 وسويتش 2960 وحاسبين وServer-PT. فعّل Server → Services → HTTP. أدخل العناوين والبوابات قبل ACL واختبر baseline في نسخة دون قواعد.
  2. مع WEB_ONLY افتح http://192.168.20.10 من A ومن B واختبر ping من كليهما. اقرأ العدادات قبل وبعد كل تجربة.
  3. نفذ المرحلة الثانية بعد إنهاء الأولى: أزل تطبيق ACL الممتدة ثم طبق ACL القياسية outbound نحو الخادم. لا تخلط نتيجتي المرحلتين.

نفذ أوامر كل جهاز في CLI الخاص به. تعليمات GUI والنصوص التفسيرية ليست أوامر IOS. اقبل اسم ملف الحفظ الافتراضي بالضغط Enter. عند اختلاف دعم أمر، وثق الإصدار والخطأ بدل الادعاء بنجاحه.

٦. التحقق ومعايير النجاح

show ip interface g0/0

PC-A/PC-B

في المرحلة الأولى HTTP من A يعمل، وHTTP من B وping للخادم من كليهما مرفوضة حسب القواعد.

في المرحلة الثانية المصدر B ممنوع لأي خدمة إلى الخادم وA مسموح. الترتيب أول تطابق وImplicit deny في النهاية.

سجل المخرجات الفعلية؛ لا تحول النتيجة المتوقعة إلى ادعاء اختبار. بعض أوامر المنصة وواجهات GUI تختلف حسب الإصدار.

٧. استكشاف الأعطال

يدخل المدرب عطلًا واحدًا في كل مرة من دليله المنفصل؛ لا تنشر الحلول أو أسرارًا حقيقية في تقرير الطالب.

٨. الأسئلة والتسليم والتقييم

  1. ما الدليل الذي يثبت كل هدف تعلم؟
  2. اختر عطلين: لماذا حدث العَرَض وما أقل إصلاح مبرر؟
  3. ما الذي لم تختبره المنصة، وما حدود الاستنتاج؟

التسليم: ملف عملك .pkt عند استخدام Packet Tracer، أو النصوص/ورقة التصميم للورش، وجدول الإعدادات، ومخرجات التحقق، وتقرير عطلين. معيار عام100: الإعداد30، صحة القيم20، التحقق25، التشخيص25؛ قد يطبق المدرب توزيع التقييم الختامي المحدد في دليله.

Lab 13: Standard and Extended IPv4 ACLs

CCNA 200-301 v1.1 • Eng. Magdi Alnaeem • 90 minutes

1. Learning objectives and prerequisites

  • Apply ordered rules and test permitted and denied traffic.
  • Distinguish source-only standard ACLs from extended service/destination rules.

Topic: 5.6 ACL configuration and verification

Prerequisites: IPv4, CLI and basic switching/routing; review relevant earlier labs. Workshops use the tools specified below.

Start in a new isolated lab file. These commands were not executed in Packet Tracer while preparing this package.

3. Addressing and settings

ItemValue
PC-A / PC-B192.168.10.10 / .11 /24; gateway .1
Server192.168.20.10/24; gateway 192.168.20.1
R1 Gi0/0 / Gi0/1192.168.10.1/24 / 192.168.20.1/24

IPv4 /24 means255.255.255.0 and /30 means255.255.255.252. Set PC addresses under Desktop → IP Configuration; never assign network/broadcast addresses. IPv6 /64 is separate from IPv4 masks.

4. Execution steps

  1. Use a 2911, 2960, two PCs and Server-PT. Enable Server → Services → HTTP. Set addressing and gateways and test baseline in a copy before applying ACLs.
  2. With WEB_ONLY open http://192.168.20.10 from A and B, and ping from each. Record ACL counters before/after.
  3. For stage 2, remove the extended ACL interface binding, then apply the standard ACL outbound toward the server. Keep stage results separate.

Run each device block on that device. GUI instructions and explanatory text are not IOS commands. Press Enter to accept the default save filename. If a command is unsupported, document the image/error rather than claiming success.

PC-A/PC-B

ping 192.168.20.10

Stage 1 allows A HTTP; B HTTP and both clients’ server pings are denied.

Stage 2 denies B any service toward the server and permits A. Rules use first match with implicit deny at the end.
