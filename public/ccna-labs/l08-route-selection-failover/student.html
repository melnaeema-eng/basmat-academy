مختبر 8: اختيار المسار والافتراضي والاحتياطي

CCNA 200-301 v1.1 • المهندس مجدي النعيم • 90 دقيقة

Packet Tracer

تحميل أوامر الإعداد TXT

١. أهداف التعلم والمتطلبات

  • تمييز Longest Prefix Match عن AD وMetric.
  • إثبات انتقال الاتصال لمسار احتياطي عند تعطل الوصلة.

الموضوع: 3.1–3.3 route selection and IPv4 static routing

المتطلبات: IPv4 وCLI وأساسيات VLAN والتوجيه؛ راجع المختبرات السابقة المناسبة. للورش استخدم الأدوات المحددة أدناه.

ابدأ بملف مختبر جديد معزول. لم تُشغّل هذه الأوامر على Packet Tracer ضمن إعداد الحزمة.

٢. المخطط والأجهزة والتوصيلات

الأجهزة والأدوات مذكورة في خطوات التنفيذ؛ معرفات L تقابل جدول المنافذ أدناه. الوصلات المسماة Logical لا تمثل كابلات فعلية.

٣. جدول العناوين والإعدادات

العنصرالقيمة
PC-A192.168.10.10/24; gateway 192.168.10.1
R1/R2 Gi0/110.0.12.1 / .2 /30
R1/R2 Gi0/210.0.13.1 / .2 /30
R2 Lo0203.0.113.9/32

الاختصار /24 يعني 255.255.255.0، و/30 يعني 255.255.255.252. أدخل عناوين PC من Desktop → IP Configuration، ولا تستخدم عنوان الشبكة أو البث. IPv6 /64 مستقل عن أقنعة IPv4.

٤. خطوات التنفيذ

  1. اختبر PC-A إلى 203.0.113.9 قبل إضافة Host Route. افصل R1 Gi0/1 إداريًا ثم أعده؛ افحص جدول التوجيه في كل مرة.
  2. أضف مرحلة Host Route بعد استعادة الأساسي. قارِن المسار نحو .9 بالافتراضي؛ الأكثر تخصيصًا يُختار رغم AD 210.
  3. أزل فقط Host Route الذي أضفته لإعادة تجربة الافتراضي، ثم احفظ جدول النتائج.

نفذ أوامر كل جهاز في CLI الخاص به. تعليمات GUI والنصوص التفسيرية ليست أوامر IOS. اقبل اسم ملف الحفظ الافتراضي بالضغط Enter. عند اختلاف دعم أمر، وثق الإصدار والخطأ بدل الادعاء بنجاحه.

في البداية الافتراضي AD 1 عبر 10.0.12.2. عند سقوط الوصلة يتثبت AD 200 عبر 10.0.13.2.

Host Route /32 يتقدم على /0؛ AD تقارن مصادر المسار لنفس Prefix. إغلاق الوصلة محليًا لا يحاكي فشلًا بعيدًا والوصلة ما زالت up.

سجل المخرجات الفعلية؛ لا تحول النتيجة المتوقعة إلى ادعاء اختبار. بعض أوامر المنصة وواجهات GUI تختلف حسب الإصدار.

Lab 8: Route Selection, Default and Floating Static Failover

CCNA 200-301 v1.1 • Eng. Magdi Alnaeem • 90 minutes

Packet Tracer

Download configuration TXT

1. Learning objectives and prerequisites

  • Distinguish longest-prefix match from AD and metric.
  • Demonstrate a floating route after link failure.

Topic: 3.1–3.3 route selection and IPv4 static routing

Prerequisites: IPv4, CLI and basic switching/routing; review relevant earlier labs. Workshops use the tools specified below.

Start in a new isolated lab file. These commands were not executed in Packet Tracer while preparing this package.

3. Addressing and settings

ItemValue

IPv4 /24 means255.255.255.0 and /30 means255.255.255.252. Set PC addresses under Desktop → IP Configuration; never assign network/broadcast addresses. IPv6 /64 is separate from IPv4 masks.

4. Execution steps

  1. Test PC-A to 203.0.113.9 before adding the host route. Administratively shut R1 Gi0/1, inspect routes, then restore it.
  2. After restoring the primary, add the host route. Compare the .9 path against default: the more specific route wins despite AD 210.
  3. Remove only the added host route to repeat the default-route test and record results.

Run each device block on that device. GUI instructions and explanatory text are not IOS commands. Press Enter to accept the default save filename. If a command is unsupported, document the image/error rather than claiming success.

6. Verification and success criteria

R1

show ip route
show ip route 203.0.113.9
show ip interface brief

PC-A

ping 203.0.113.9
tracert 203.0.113.9

Initially default AD 1 uses 10.0.12.2; after link failure AD 200 uses 10.0.13.2.

The /32 wins over /0; AD compares routes to the same prefix. Local link shutdown does not simulate a remote failure while the local link stays up.

Record actual outputs; expected results are not test execution claims. Some commands and GUI labels vary by platform/release.
