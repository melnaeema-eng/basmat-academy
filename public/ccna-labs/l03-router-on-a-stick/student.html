مختبر ٣: التوجيه بين VLANs باستخدام Router-on-a-Stick

CCNA 200-301 • المهندس مجدي النعيم • المدة: ٩٠ دقيقة

ورقة المتدرب — Cisco Packet Tracer

١. الأهداف والمتطلبات

استكمال المختبر الثاني: كانت VLAN 10 و20 منفصلتين بلا توجيه. أضف راوترًا لتفعيل الاتصال بينهما باستخدام واجهة فعلية واحدة وSubinterfaces.

  • إعداد 802.1Q Subinterfaces وربط كل واجهة بـVLAN محددة.
  • إعداد بوابات الحاسبات ووصلة Trunk إلى الراوتر.
  • تمييز الشبكات المتصلة مباشرة عن Static Routes.
  • تشخيص خطأ VLAN tag أو البوابة أو قائمة Allowed VLANs.

المتطلبات السابقة: مختبر VLANs وTrunk، أساسيات IPv4 وCLI. موضوع المنهج: Network Access وIP Connectivity.

٢. الأجهزة ومخطط الشبكة

راوتر Cisco 2911 واحد، وسويتشان 2960-24TT، وأربعة حواسب PC. يمكن متابعة ملف المختبر الثاني بعد حفظ نسخة جديدة باسم CCNA-L03-YourName.pkt.

الوصلةالكابل
R1 Gi0/0 ↔ SW1 Gi0/2Straight-through
SW1 Gi0/1 ↔ SW2 Gi0/1Crossover
PC-A ↔ SW1 Fa0/1، PC-B ↔ SW1 Fa0/2Straight-through
PC-C ↔ SW2 Fa0/1، PC-D ↔ SW2 Fa0/2Straight-through

٣. العنونة والتوصيل — ١٥ دقيقة

القناع لكل الحاسبات: 255.255.255.0. أدخل الإعدادات من Desktop → IP Configuration.

الجهازIPv4VLANDefault Gateway
PC-A192.168.10.1110192.168.10.1
PC-C192.168.10.1210192.168.10.1
PC-B192.168.20.1120192.168.20.1
PC-D192.168.20.1220192.168.20.1

قبل تشغيل الراوتر: تحقق أن A يصل إلى C وB يصل إلى D، بينما الاتصال بين VLANs لا يعمل. سجّل هذه النتيجة للمقارنة بعد الإعداد.

R1 — الواجهات الفرعية

enable
configure terminal
hostname R1
no ip domain-lookup
interface gigabitEthernet 0/0
description TRUNK_TO_SW1
no ip address
no shutdown
exit
interface gigabitEthernet 0/0.10
encapsulation dot1Q 10
ip address 192.168.10.1 255.255.255.0
exit
interface gigabitEthernet 0/0.20
encapsulation dot1Q 20
ip address 192.168.20.1 255.255.255.0
exit
interface gigabitEthernet 0/0.999
encapsulation dot1Q 999 native
no ip address
exit
end
copy running-config startup-config

الواجهة الفعلية Gi0/0 لا تحمل IP. عنوان كل بوابة على الواجهة الفرعية المقابلة. VLAN 999 هي Native غير مستخدمة للمستخدمين ومتطابقة على طرفي الوصلة. لا يلزم Static Route للشبكتين لأنهما متصلتان مباشرة بالراوتر. اضغط Enter لقبول اسم ملف الحفظ الافتراضي.

٥. التحقق — ٢٠ دقيقة

على R1:

show ip interface brief
show ip route
show interfaces gigabitEthernet 0/0.10
show interfaces gigabitEthernet 0/0.20
show running-config

المتوقع: Gi0/0 وواجهتا .10 و.20 بحالة up/up. تظهر الشبكتان 192.168.10.0/24 و192.168.20.0/24 بالرمز C، وعناوين البوابات بالرمز L. حالة up/up وحدها لا تثبت صحة VLAN tag؛ قارن encapsulation في الإعداد.

على السويتشين:

show vlan brief
show interfaces trunk
show interfaces gigabitEthernet 0/1 switchport

وعلى SW1 أيضًا:

show interfaces gigabitEthernet 0/2 switchport

يجب أن تحمل وصلتا Trunk على SW1 الشبكات 10 و20 و999، وNative VLAN 999.

من PC-A:

ipconfig
ping 192.168.10.1
ping 192.168.10.12
ping 192.168.20.1
ping 192.168.20.11
ping 192.168.20.12
tracert 192.168.20.12

كرّر من PC-D إلى 192.168.10.11. قد تفقد أول حزمة بسبب ARP؛ انتظر تقارب STP ثم أعد الاختبار. معيار النجاح: اتصال كل حاسب ببوابته، ونجاح A↔C وB↔D، ثم A↔D وB↔C. يمر الاتصال بين الشبكتين عبر R1؛ لا تعتمد على شكل traceroute وحده لأن عرض المحاكي قد يختلف.

٧. أسئلة وتسليم — ١٠ دقائق

  1. لماذا لم نستخدم عنوان IP على Gi0/0 الفعلية؟
  2. ما وظيفة encapsulation dot1Q 20؟
  3. لماذا لا نحتاج Static Routes بين هاتين الشبكتين؟
  4. هل رقم الواجهة الفرعية يجب أن يطابق VLAN ID؟ اشرح الفرق بين التسمية ووسم الإطار.
  5. لماذا لا يثبت نجاح ping داخل VLAN سلامة البوابة الافتراضية؟

Student worksheet — Cisco Packet Tracer

1. Objectives and prerequisites

  • Extend Lab 2 by routing between VLAN 10 and VLAN 20.
  • Create 802.1Q router subinterfaces and set host gateways.
  • Interpret connected routes without adding unnecessary static routes.
  • Diagnose gateway, VLAN tag, interface and allowed-list faults.

Prerequisites: Lab 2, IPv4 and IOS CLI. Time plan: addressing/cabling 15, configuration 30, verification 20, troubleshooting 15, submission 10 minutes.

Gi0/0 has no IP address. Each VLAN gateway lives on its corresponding subinterface. Native VLAN 999 matches the switch and has no user IP. The two LANs are directly connected to R1, so no static routes are required. Accept the default save filename.

5. Verification

R1

show ip interface brief
show ip route
show interfaces gigabitEthernet 0/0.10
show interfaces gigabitEthernet 0/0.20
show running-config

Gi0/0 and .10/.20 should be up/up; the route table contains C routes for 192.168.10.0/24 and 192.168.20.0/24 plus L routes for gateway addresses. Up/up alone does not validate the VLAN tag: inspect encapsulation.

Both switches

show vlan brief
show interfaces trunk
show interfaces gigabitEthernet 0/1 switchport

SW1 additionally

show interfaces gigabitEthernet 0/2 switchport

Both SW1 trunks must allow 10,20,999 and use native VLAN 999.

PC-A

ipconfig
ping 192.168.10.1
ping 192.168.10.12
ping 192.168.20.1
ping 192.168.20.11
ping 192.168.20.12
tracert 192.168.20.12

Also test PC-D → 192.168.10.11. After ARP/STP settle, each PC must reach its own gateway; A↔C, B↔D, A↔D and B↔C must pass. Cross-VLAN traffic traverses R1. Traceroute formatting may vary.

Introduce one fault at a time. Record the command evidence, diagnosis, correction and retest.

7. Questions and submission

  1. Why does parent interface Gi0/0 have no IP address?
  2. What does encapsulation dot1Q 20 do?
  3. Why are static routes unnecessary for these two LANs?
  4. Must the subinterface number equal the VLAN ID? Distinguish its label from the actual tag.
  5. Why does same-VLAN ping not validate the default gateway?

Submit the .pkt file, address table, before/after verification and two fault reports. Scoring: VLANs/trunks 25, subinterfaces/gateways 30, verification 20, troubleshooting 25.
