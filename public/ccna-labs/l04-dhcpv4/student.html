مختبر ٤: توزيع IPv4 تلقائيًا باستخدام DHCP عبر VLANs

CCNA 200-301 • المهندس مجدي النعيم • ٩٠ دقيقة

١. الأهداف والمتطلبات

  • إعداد DHCP Pool مستقلة لكل VLAN.
  • استثناء البوابات والعناوين المحجوزة من التوزيع.
  • تحويل الحاسبات من Static إلى DHCP والتحقق من العنوان والقناع والبوابة.
  • تتبع DORA وتشخيص فشل الحصول على عنوان أو بوابة صحيحة.

المتطلبات السابقة: المختبر الثالث بحالة تشغيل سليمة. موضوع المنهج: IP Services. توزيع الوقت: ١٥ دقيقة تجهيز، ٢٠ إعداد DHCP، ٢٠ تحقق، ٢٠ أعطال، ١٥ أسئلة وتسليم.

٢. السيناريو والأجهزة

استكمل Router-on-a-Stick من المختبر الثالث. سيتولى R1 توزيع العناوين لشبكتي المبيعات والدعم بدل إدخالها يدويًا. استخدم Cisco 2911 واحدًا، وسويتشين 2960-24TT وأربعة PCs.

الوصلةالكابل
R1 Gi0/0 ↔ SW1 Gi0/2Straight-through
SW1 Gi0/1 ↔ SW2 Gi0/1Crossover
PC-A ↔ SW1 Fa0/1; PC-B ↔ SW1 Fa0/2Straight-through
PC-C ↔ SW2 Fa0/1; PC-D ↔ SW2 Fa0/2Straight-through

٣. خطة العناوين والتجهيز

VLANالشبكة والقناعالبوابةالمستثنىالنطاق المتاح
10 SALES192.168.10.0/24192.168.10.1.1 إلى .20.21 إلى .254
20 SUPPORT192.168.20.0/24192.168.20.1.1 إلى .20.21 إلى .254

القناع: 255.255.255.0. يحتفظ R1 بعنواني البوابة الثابتين. استخدم إعدادات الحاسبات الثابتة من المختبر الثالث أولًا لإثبات سلامة الاتصال، ثم حوّلها إلى DHCP بعد إعداد الخادم. لا تفترض حصول PC معين على عنوان ثابت من النطاق.

الخادم هو الراوتر المتصل مباشرة بالـVLANs؛ لا نستخدم ip helper-address هنا. لم نضف DNS أو إنترنت لهذا التمرين؛ نجاح ping بالعناوين لا يختبر DNS.

اضغط Enter لقبول اسم ملف الحفظ. إذا كان الملف من مختبر سابق يتضمن DHCP فتأكد من عدم وجود Pools أو استثناءات متعارضة قبل البدء.

٥. تحويل الحاسبات والتحقق

  1. افتح Desktop → IP Configuration على الحاسبات الأربعة واضغط DHCP.
  2. تحقق من اكتمال الطلب ثم سجل عنوان كل حاسب وقناعه وبوابته.
  3. يجب أن يحصل A وC على عنوان من 192.168.10.21–254، ويحصل B وD على عنوان من 192.168.20.21–254، مع بوابة الشبكة الصحيحة.
  4. في Simulation Mode فعّل مرشح DHCP، ثم أعد طلب عنوان من أحد الحاسبات بمفتاح Static ثم DHCP لملاحظة الرسائل. في عملية اكتساب جديدة راقب Discover → Offer → Request → ACK؛ إعادة التجديد قد لا تعيد التسلسل كاملًا.

على R1:

show ip dhcp pool
show ip dhcp binding
show ip dhcp conflict
show ip interface brief
show ip route
show running-config

توقع Pool لكل شبكة، وBinding لكل عميل حصل على Lease. في ملف نظيف وبعد نجاح الحاسبات الأربعة يجب وجود أربع عمليات ربط فعالة. قد تظهر سجلات قديمة إن أُعيد استخدام الملف؛ لا تساوِ عدد السجلات التاريخية بعدد الحاسبات الحالية.

على كل PC:

ipconfig

من PC-A نفذ ping إلى 192.168.10.1 ثم 192.168.20.1، ثم إلى عنوان PC-C وعنوان PC-D اللذين سجلتهما فعليًا. اختبر العودة من PC-D إلى PC-A. لا تنسخ عنوانًا افتراضيًا للحاسبات؛ عنوان DHCP قد يتغير.

افحص Trunks بـshow interfaces trunk وعضوية Access بـshow vlan brief عند فشل طلبات أحد الأقسام. قد تحتاج إعادة ping بعد ARP.

٦. تمارين الأعطال

العَرَضما يفحصه المتدرب
كل الحاسبات تفشل في اكتساب Lease جديدةservice dhcp وحالة الواجهة والـTrunks
VLAN واحدة فقط لا تحصل على عنوانnetwork والقناع في Pool وAllowed VLANs
العنوان والقناع صحيحان، الاتصال المحلي يعمل، لكن الشبكة الأخرى لا تعملdefault-router في Pool والبوابة الفعلية عند العميل
حاسب واحد فقط يحتفظ بعنوانه القديمهل اختير DHCP فعلًا؟ وهل اكتمل طلب جديد؟

يطبق المدرب عطلًا واحدًا ثم يطلب اكتساب Lease جديدة لإظهار أثره؛ العملاء أصحاب Leases سابقة قد يستمرون مؤقتًا. سجل العطل والدليل والإصلاح وأعد اختبار عميل متأثر. لا تحذف جميع Bindings لمجرد التشخيص.

٧. الأسئلة والتسليم

  1. لماذا استثنينا .1–.20؟
  2. ما الفرق بين network وdefault-router داخل Pool؟
  3. لماذا لا نحتاج DHCP Relay هنا؟
  4. هل وجود Binding وحده يثبت صحة البوابة؟
  5. لماذا قد يستمر حاسب بالعمل بعد تعطيل خدمة DHCP؟

سلّم CCNA-L04-YourName.pkt، وجدول العناوين المكتسبة، ومخرجات Pool وBinding، ودليل DORA ونتائج ping، وتقرير عطلين. التقييم: الاستثناءات وPools ٣٠، صحة بيانات العملاء ٢٥، التحقق وDORA ٢٠، تشخيص الأعطال ٢٥.

لا يوجد ملف .pkt جاهز أو تشغيل فعلي للمحاكاة ضمن الحزمة. أسئلة الورقة تدريبية، وربط درجاتها بالدورة لم يُنفذ بعد. حلول المدرب منفصلة.

Lab 4: Automatic IPv4 Addressing with DHCP Across VLANs

CCNA 200-301 • Eng. Magdi Alnaeem • 90 minutes

1. Objectives and prerequisites

  • Create a DHCP pool for each VLAN.
  • Exclude gateway and reserved infrastructure addresses.
  • Replace static PC addressing with DHCP and verify the address, mask and gateway.
  • Observe DORA and diagnose lease acquisition and gateway faults.

Prerequisite: a working Lab 3 topology. Topic: IP Services. Time plan: preparation 15, DHCP setup 20, verification 20, troubleshooting 20, questions/submission 15 minutes.

2. Scenario and equipment

Extend the previous router-on-a-stick lab. R1 now allocates addresses for Sales and Support. Use one Cisco 2911, two 2960-24TT switches and four PCs.

ConnectionCable
R1 Gi0/0 ↔ SW1 Gi0/2Straight-through
SW1 Gi0/1 ↔ SW2 Gi0/1Crossover
PC-A ↔ SW1 Fa0/1; PC-B ↔ SW1 Fa0/2Straight-through
PC-C ↔ SW2 Fa0/1; PC-D ↔ SW2 Fa0/2Straight-through

3. Address plan and preparation

VLANSubnetGatewayExcludedAvailable
10 SALES192.168.10.0/24192.168.10.1.1–.20.21–.254
20 SUPPORT192.168.20.0/24192.168.20.1.1–.20.21–.254

The mask is 255.255.255.0. Keep the router gateway addresses static. First verify connectivity with the Lab 3 static PC settings, then switch clients to DHCP after configuring the server. Never assume a particular client will always receive a specific address.

R1 is directly attached to both VLANs, so no ip helper-address is required. This topology provides no DNS server or Internet service; IP ping does not test DNS.

Accept the default save filename. If reusing a file with existing DHCP configuration, check for conflicting pools and exclusions before starting.

5. Enable DHCP and verify

  1. On each PC, open Desktop → IP Configuration and select DHCP.
  2. Wait for acquisition and record each address, mask and gateway.
  3. A/C must receive 192.168.10.21–254 with gateway 192.168.10.1; B/D must receive 192.168.20.21–254 with gateway 192.168.20.1.
  4. Use Simulation Mode with the DHCP filter. Toggle one PC to Static and back to DHCP to request an address. For a fresh acquisition observe Discover → Offer → Request → ACK. A renewal may not repeat all four messages.

On R1:

show ip dhcp pool
show ip dhcp binding
show ip dhcp conflict
show ip interface brief
show ip route
show running-config

Expect one pool per subnet and a binding for each client with an allocated lease. A clean topology with four successful clients should have four active bindings. Reused files may retain old records; historical record counts need not equal current client counts.

On every PC:

ipconfig

From PC-A, ping 192.168.10.1, then 192.168.20.1, then the actual recorded addresses of PC-C and PC-D. Verify the reverse path from PC-D to PC-A. Use recorded leases rather than guessed addresses. Repeat an initial ping after ARP learning if needed.

For a department-specific failure, inspect show interfaces trunk and show vlan brief before changing the DHCP configuration.

6. Troubleshooting exercises

SymptomInvestigate
All PCs fail to acquire new leasesDHCP service state, parent interface and trunks
Only one VLAN fails to obtain an addressPool network/mask and trunk allowed list
Correct address and local traffic, but remote VLAN failsPool default-router and the actual client gateway
One PC retains an old static addressWhether DHCP was selected and a new request completed

Introduce one fault at a time and request a fresh lease to expose its effect. Clients with existing leases may continue working temporarily. Record evidence, correction and a client retest. Do not clear all bindings merely to troubleshoot.

7. Questions and submission

  1. Why exclude .1–.20?
  2. Distinguish network and default-router pool options.
  3. Why is DHCP relay unnecessary here?
  4. Does a binding alone prove the gateway is correct?
  5. Why might a client keep working after DHCP service is disabled?

Submit CCNA-L04-YourName.pkt, the acquired addressing table, pool/binding outputs, DORA evidence, ping results and two fault reports. Scoring: pools/exclusions 30, client settings 25, verification/DORA 20, troubleshooting 25.
