١. أهداف التعلم والمتطلبات

  • بناء شبكة متعددة الخدمات والتحقق طبقة بطبقة.
  • ربط العنونة والتوجيه والترجمة والسياسة دون خلط أدوارها.

الموضوع: Integrated domains 1–5

المتطلبات: IPv4 وCLI وأساسيات VLAN والتوجيه؛ راجع المختبرات السابقة المناسبة. للورش استخدم الأدوات المحددة أدناه.

ابدأ بملف مختبر جديد معزول. لم تُشغّل هذه الأوامر على Packet Tracer ضمن إعداد الحزمة.

٤. خطوات التنفيذ

  1. استخدم ثلاثة2911 وسويتش2960 وحاسبين. قبل الإعداد اكتب مصفوفة المطلوب: DHCP صحيح، اتصال خارجي للحاسبين، منع users إلى services.
  2. نفذ L2 والواجهات أولًا ثم DHCP، وبعده OSPF والافتراضي ثم NAT ثم ACL. سجّل baseline عند كل مرحلة بدل تغيير كل شيء عشوائيًا.
  3. اختر DHCP على PC-A وB. استخدم العناوين المكتسبة الفعلية لاختبار منع A→B ثم اختبر الهدف الخارجي من كليهما.
  4. احفظ الملف ولقطات أدلة show لكل متطلب؛ وثّق Policy وNAT route-return ولا تضف route للشبكات الخاصة على ISP لتجاوز NAT.

نفذ أوامر كل جهاز في CLI الخاص به. تعليمات GUI والنصوص التفسيرية ليست أوامر IOS. اقبل اسم ملف الحفظ الافتراضي بالضغط Enter. عند اختلاف دعم أمر، وثق الإصدار والخطأ بدل الادعاء بنجاحه.

1. Learning objectives and prerequisites

  • Build a multi-service topology and verify it layer by layer.
  • Connect addressing, routing, translation and access policy without conflating them.

Topic: Integrated domains 1–5

Prerequisites: IPv4, CLI and basic switching/routing; review relevant earlier labs. Workshops use the tools specified below.

Start in a new isolated lab file. These commands were not executed in Packet Tracer while preparing this package.

3. Addressing and settings

ItemValue

IPv4 /24 means255.255.255.0 and /30 means255.255.255.252. Set PC addresses under Desktop → IP Configuration; never assign network/broadcast addresses. IPv6 /64 is separate from IPv4 masks.

4. Execution steps

  1. Use three2911s, one2960 and two PCs. Before setup write a requirements matrix: correct DHCP, outside reachability for both clients, and users-to-services denied.
  2. Implement L2/interfaces, then DHCP, then OSPF/default, then NAT, then ACL. Record a baseline at each stage instead of changing everything at random.
  3. Select DHCP on both clients. Use their actual leased addresses to test denied A→B, then test the outside target from both.
  4. Save the topology and evidence for each requirement. Document policy and NAT return forwarding; do not add ISP private routes to bypass NAT.

Run each device block on that device. GUI instructions and explanatory text are not IOS commands. Press Enter to accept the default save filename. If a command is unsupported, document the image/error rather than claiming success.

Both clients reach203.0.113.10 through PAT. A cannot reach B under policy; a stateless ACL can also block A’s reply to B-initiated traffic, so do not claim reverse access is permitted.
