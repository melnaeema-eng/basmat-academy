مختبر ٢: إنشاء VLANs وربط سويتشين باستخدام 802.1Q Trunk

CCNA 200-301 • المهندس مجدي النعيم • ٩٠ دقيقة

ورقة المتدرب — Cisco Packet Tracer

١. أهداف التعلم

  • إنشاء VLAN 10 للمبيعات وVLAN 20 للدعم على سويتشين.
  • إسناد منافذ المستخدمين إلى Access VLAN الصحيحة.
  • إعداد Trunk ثابت، وتحديد Allowed VLANs وNative VLAN بصورة متطابقة.
  • إثبات الاتصال داخل VLAN نفسها عبر السويتشين، وعزل الشبكتين دون جهاز توجيه.
  • تشخيص أخطاء عضوية المنافذ وقائمة VLANs وحالة الوصلة.

المتطلبات: أساسيات Ethernet وIPv4 وCLI. موضوع المنهج: Network Access — VLANs و802.1Q Trunking. هذا مختبر طبقة ثانية مستقل عن مختبر VLSM السابق.

٢. السيناريو والأجهزة

تعمل المبيعات والدعم في طابقين. مطلوب أن تتواصل أجهزة القسم نفسه عبر الطابقين، مع فصل القسمين منطقيًا. استخدم سويتشين 2960-24TT وأربعة أجهزة PC. لا تضف راوترًا ولا Multilayer Switch في هذا المختبر.

٣. إعداد الحاسبات — ١٥ دقيقة

بعد التوصيل، افتح Desktop → IP Configuration في كل حاسب. القناع للجميع 255.255.255.0. اترك Default Gateway فارغة؛ لا توجد خدمة توجيه بين الشبكتين.

الجهازالقسم / VLANIPv4
PC-ASALES / 10192.168.10.11
PC-CSALES / 10192.168.10.12
PC-BSUPPORT / 20192.168.20.11
PC-DSUPPORT / 20192.168.20.12

دوّن توقعك قبل الإعداد: أي الأزواج يجب أن تتصل وأيها يجب أن يفشل؟

٤. إعداد السويتشين — ٢٥ دقيقة

افتح CLI لكل سويتش. إذا ظهر معالج الإعداد الأولي، ارفضه باستخدام no. أوامر 2960 تستخدم 802.1Q دون الحاجة إلى switchport trunk encapsulation dot1q؛ قد يرفض هذا الأمر على هذا الطراز.

SW1

enable
configure terminal
hostname SW1
no ip domain-lookup
vlan 10
name SALES
exit
vlan 20
name SUPPORT
exit
vlan 999
name NATIVE_UNUSED
exit
interface fastEthernet 0/1
description SALES_PC
switchport mode access
switchport access vlan 10
spanning-tree portfast
no shutdown
exit
interface fastEthernet 0/2
description SUPPORT_PC
switchport mode access
switchport access vlan 20
spanning-tree portfast
no shutdown
exit
interface gigabitEthernet 0/1
description TRUNK_TO_SW2
switchport mode trunk
switchport trunk native vlan 999
switchport trunk allowed vlan 10,20,999
no shutdown
exit
end
copy running-config startup-config

SW2

enable
configure terminal
hostname SW2
no ip domain-lookup
vlan 10
name SALES
exit
vlan 20
name SUPPORT
exit
vlan 999
name NATIVE_UNUSED
exit
interface fastEthernet 0/1
description SALES_PC
switchport mode access
switchport access vlan 10
spanning-tree portfast
no shutdown
exit
interface fastEthernet 0/2
description SUPPORT_PC
switchport mode access
switchport access vlan 20
spanning-tree portfast
no shutdown
exit

description TRUNK_TO_SW1
switchport mode trunk
switchport trunk native vlan 999
switchport trunk allowed vlan 10,20,999
no shutdown
exit
end
copy running-config startup-config

اضغط Enter لقبول اسم ملف الحفظ الافتراضي. Native VLAN 999 مخصصة للوصلة ولا تُسند إلى حواسب المستخدمين. لا تفعّل PortFast على وصلة السويتشين.

٥. التحقق — ٢٠ دقيقة

على السويتشين:

show vlan brief
show interfaces trunk
show interfaces fastEthernet 0/1 switchport
show interfaces fastEthernet 0/2 switchport
show interfaces gigabitEthernet 0/1 switchport
show interfaces status
show mac address-table dynamic
الفحصالنتيجة المتوقعة
show vlan briefVLAN 10 و20 و999 موجودة؛ Fa0/1 في 10 وFa0/2 في 20
show interfaces trunkGi0/1 trunking، Native 999، Allowed 10,20,999 على الطرفين
show interfaces … switchportوضع access وVLAN صحيحة لمنافذ الحاسبات؛ وضع trunk لمنفذ الربط
MAC table بعد pingتعلم عناوين الحاسبات ضمن VLAN المعنية؛ الحاسب البعيد عبر Gi0/1

من PC-A:

ping 192.168.10.12
ping 192.168.20.11

من PC-B:

ping 192.168.20.12
ping 192.168.10.12

كرّر الاختبارات من PC-C إلى PC-A ومن PC-D إلى PC-B. انتظر اكتمال STP وARP ثم أعد الاختبار عند فقد أول حزمة.

الاختبارالمتوقع
A ↔ Cنجاح: VLAN 10 عبر Trunk
B ↔ Dنجاح: VLAN 20 عبر Trunk
A → B وB → Cفشل متوقع: شبكتان مختلفتان بلا توجيه

فشل الاتصال بين شبكتين مختلفتين وحده لا يثبت ضبط VLAN بصورة صحيحة؛ يجب أيضًا إثبات عضوية المنافذ وحالة Trunk ونجاح الاتصال داخل كل VLAN.

٦. تمارين الأعطال — ٢٠ دقيقة

يطبق المدرب عطلًا واحدًا في كل مرة. قبل أي تغيير، دوّن العرض والدليل والسبب المرجح، ثم الإصلاح ونتيجة إعادة الاختبار.

الحالةالعرض المتوقعأداة البداية

VLAN مفقودة من Allowed listقسم واحد يتوقف عبر الوصلة والآخر يعملshow interfaces trunk
إغلاق منفذ Trunkالقسمان يفشلان عبر السويتشينshow interfaces status
Native VLAN مختلفة بين الطرفينقد يظهر تحذير mismatch؛ نجاح بيانات 10 و20 لا ينفي الخطأمقارنة Native VLAN على الطرفين

قد تؤدي اختلافات Native VLAN إلى سلوك STP مختلف حسب النظام والمحاكي؛ لا تفترض عرضًا واحدًا ثابتًا. معيار التشخيص هو مقارنة إعداد الطرفين.

٧. أسئلة وتسليم — ١٠ دقائق

  1. لماذا نجح الاتصال داخل VLAN واحدة عبر سويتشين؟
  2. ما الفرق بين Access VLAN وNative VLAN وAllowed VLAN list؟
  3. هل يكفي تغيير Default Gateway لربط VLAN 10 و20؟ فسّر.
  4. لماذا لا يظهر منفذ Trunk كمنفذ Access تحت VLAN 10 في show vlan brief؟
  5. كيف تشخّص توقف VLAN 20 مع استمرار VLAN 10؟

التسليم: ملف CCNA-L02-YourName.pkt، ونتائج أوامر التحقق، ومصفوفة ping، وتشخيص عطلين. التقييم: VLANs وAccess ٢٥، Trunk ٢٥، التحقق والعزل ٢٥، تشخيص الأعطال ٢٥.

هذه الأسئلة تدريبية في ورقة المختبر وليست اختبارًا إلكترونيًا مرتبطًا بنتيجة الدورة. لم يُنشأ ملف .pkt ولم تُشغّل محاكاة فعلية ضمن هذه الحزمة؛ يُنشئ المتدرب ملفه أثناء التنفيذ.
