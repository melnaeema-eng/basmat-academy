مختبر ١: تقسيم الشبكات VLSM وربط فرعين بالتوجيه الثابت

CCNA 200-301 • بإشراف المهندس مجدي النعيم • المدة: ٩٠ دقيقة

ورقة المتدرب — Cisco Packet Tracer

١. أهداف التعلم والمتطلبات

  • تقسيم شبكة IPv4 باستخدام VLSM دون تداخل.
  • إعداد واجهات الراوتر وعناوين الحاسبين والبوابات الافتراضية.
  • إضافة Static Routes والتحقق من مسار الذهاب والعودة.
  • تشخيص أعطال العنونة والواجهات والتوجيه بأدلة واضحة.

المتطلبات السابقة: أساسيات IPv4 وSubnetting وCIDR وأوامر Cisco IOS. هذا تمرين تطبيقي في Network Fundamentals وIP Connectivity.

٢. السيناريو

اربط مقرًا يحتاج إلى ٥٠ عنوانًا للأجهزة بالإضافة إلى البوابة بفرع يحتاج إلى ٢٥ عنوانًا للأجهزة بالإضافة إلى البوابة. خصص شبكة مستقلة لوصلة الراوترين ذات عنوانين. الشبكة المتاحة: 192.168.10.0/24.

المطلوب: ابدأ بأكبر شبكة، واحسب الشبكة والقناع وأول وآخر عنوان صالح وعنوان البث. لا تستخدم عنوان الشبكة أو البث لأي واجهة.

٣. مخطط الشبكة والأجهزة

الأجهزة: راوتران Cisco 2911، سويتشان Cisco 2960، وحاسبان PC. السويتشان يعملان بإعداداتهما الافتراضية ضمن VLAN 1؛ لا يلزم عنوان إدارة لهما لهذا التمرين.

٦. التحقق — ١٥ دقيقة

على الراوترين:

show ip interface brief
show ip route
show running-config

يجب أن تكون Gi0/0 وGi0/1 بحالة up/up. الرمز C يعني شبكة متصلة مباشرة، وS مسارًا ثابتًا، وL عنوان واجهة محليًا.

من PC-A:

ipconfig
ping 192.168.10.1
ping 192.168.10.98
ping 192.168.10.70
tracert 192.168.10.70

من PC-B:

ping 192.168.10.65
ping 192.168.10.10

قد يتأخر أول رد أثناء ARP؛ كرر الاختبار بعد اكتمال التعلم. معيار النجاح: استجابة الحاسبين في الاتجاهين، ووجود مسار ثابت للشبكة البعيدة على كل راوتر. في المسار من PC-A إلى PC-B توقع المرور عبر R1 ثم R2 ثم الوجهة؛ قد تختلف تفاصيل عرض traceroute حسب المحاكاة.

Lab 1: VLSM and Static Routing Between Two Sites

CCNA 200-301 • Instructor: Eng. Magdi Alnaeem • 90 minutes

Student worksheet — Cisco Packet Tracer

1. Objectives and prerequisites

  • Design non-overlapping VLSM subnets from one /24.
  • Configure router interfaces, host addresses and gateways.
  • Add static routes in both directions and interpret connected/local/static routes.
  • Diagnose addressing, interface and return-path faults.

Prerequisites: IPv4 subnetting, CIDR and basic Cisco IOS CLI. Allocate 15 minutes to planning, 10 to cabling, 25 to configuration, 15 to verification and 20 to troubleshooting; use the remaining 5 minutes for submission.

2. Scenario, topology and equipment

Use 192.168.10.0/24 for an HQ LAN with 50 hosts plus a gateway, a branch with 25 hosts plus a gateway, and a two-address router link. Allocate the largest subnet first.

Equipment: two Cisco 2911 routers, two 2960 switches and two PCs.

5. Verification

Run these commands on both routers:

show ip interface brief
show ip route
show running-config

Gi0/0 and Gi0/1 must be up/up. C indicates a connected subnet, L a local interface address and S a static route to the remote LAN.

PC-A

ipconfig
ping 192.168.10.1
ping 192.168.10.98
ping 192.168.10.70
tracert 192.168.10.70

PC-B

ping 192.168.10.65
ping 192.168.10.10

Repeat the first ping after ARP learning if needed. Both PCs must reach their own gateways and each other in both directions. The remote path traverses R1 and R2; traceroute formatting can vary in the simulator.

6. Troubleshooting exercises

Fault symptomStart by checking
PC reaches its gateway but not the branchDefault gateway and static route
Router-to-router link failsInterface state, addressing and cable
Remote subnet absent from route tableStatic route destination, mask and next hop
Router tests succeed but end-to-end PC tests failHost settings and the return route

The instructor introduces one fault at a time. Record the symptom, command output, diagnosis, correction and retest; restore normal operation before the next fault.

7. Submission and scoring

Submit the .pkt file, completed addressing table, route tables, bidirectional ping evidence and two fault reports. Scoring: addressing 25, configuration 30, verification 20 and troubleshooting 25.
