مختبر ١: تقسيم الشبكات VLSM وربط فرعين بالتوجيه الثابت

CCNA 200-301 • بإشراف المهندس مجدي النعيم • المدة: ٩٠ دقيقة

ورقة المتدرب — Cisco Packet Tracer

١. أهداف التعلم والمتطلبات

  • تقسيم شبكة IPv4 باستخدام VLSM دون تداخل.
  • إعداد واجهات الراوتر وعناوين الحاسبين والبوابات الافتراضية.
  • إضافة Static Routes والتحقق من مسار الذهاب والعودة.
  • تشخيص أعطال العنونة والواجهات والتوجيه بأدلة واضحة.

المتطلبات السابقة: أساسيات IPv4 وSubnetting وCIDR وأوامر Cisco IOS. هذا تمرين تطبيقي في Network Fundamentals وIP Connectivity.

٢. السيناريو

اربط مقرًا يحتاج إلى ٥٠ عنوانًا للأجهزة بالإضافة إلى البوابة بفرع يحتاج إلى ٢٥ عنوانًا للأجهزة بالإضافة إلى البوابة. خصص شبكة مستقلة لوصلة الراوترين ذات عنوانين. الشبكة المتاحة: 192.168.10.0/24.

المطلوب: ابدأ بأكبر شبكة، واحسب الشبكة والقناع وأول وآخر عنوان صالح وعنوان البث. لا تستخدم عنوان الشبكة أو البث لأي واجهة.

٣. مخطط الشبكة والأجهزة

الأجهزة: راوتران Cisco 2911، سويتشان Cisco 2960، وحاسبان PC. السويتشان يعملان بإعداداتهما الافتراضية ضمن VLAN 1؛ لا يلزم عنوان إدارة لهما لهذا التمرين.

٥. التوصيل والإعداد — ٣٥ دقيقة

أنشئ التوصيلات في ١٠ دقائق. من كل PC افتح Desktop → IP Configuration، وأدخل القيم التالية. نفذ إعداد الراوترين خلال ٢٥ دقيقة، ثم احفظ ملف Packet Tracer باسم CCNA-L01-YourName.pkt.

الجهازالعنوانالقناعالبوابة
PC-A192.168.10.10255.255.255.192192.168.10.1
PC-B192.168.10.70255.255.255.224192.168.10.65

أوامر R1

enable
configure terminal
hostname R1
no ip domain-lookup
interface gigabitEthernet 0/0
description HQ_LAN
ip address 192.168.10.1 255.255.255.192
no shutdown
exit
interface gigabitEthernet 0/1
description TRANSIT_TO_R2
ip address 192.168.10.97 255.255.255.252
no shutdown
exit
ip route 192.168.10.64 255.255.255.224 192.168.10.98
end
copy running-config startup-config

أوامر R2

enable
configure terminal
hostname R2
no ip domain-lookup
interface gigabitEthernet 0/0
description BRANCH_LAN
ip address 192.168.10.65 255.255.255.224
no shutdown
exit
interface gigabitEthernet 0/1
description TRANSIT_TO_R1
ip address 192.168.10.98 255.255.255.252
no shutdown
exit
ip route 192.168.10.0 255.255.255.192 192.168.10.97
end
copy running-config startup-config

عند مطالبة حفظ الإعداد باسم الوجهة، اضغط Enter لقبول الاسم الافتراضي.

٦. التحقق — ١٥ دقيقة

على الراوترين:

show ip interface brief
show ip route
show running-config

يجب أن تكون Gi0/0 وGi0/1 بحالة up/up. الرمز C يعني شبكة متصلة مباشرة، وS مسارًا ثابتًا، وL عنوان واجهة محليًا.

من PC-A:

ipconfig
ping 192.168.10.1
ping 192.168.10.98
ping 192.168.10.70
tracert 192.168.10.70

من PC-B:

ping 192.168.10.65
ping 192.168.10.10

قد يتأخر أول رد أثناء ARP؛ كرر الاختبار بعد اكتمال التعلم. معيار النجاح: استجابة الحاسبين في الاتجاهين، ووجود مسار ثابت للشبكة البعيدة على كل راوتر. في المسار من PC-A إلى PC-B توقع المرور عبر R1 ثم R2 ثم الوجهة؛ قد تختلف تفاصيل عرض traceroute حسب المحاكاة.

٧. استكشاف الأعطال — ٢٠ دقيقة

يطبق المدرب عطلًا واحدًا في كل مرة. لا تغيّر عدة إعدادات معًا؛ سجل الدليل قبل الإصلاح ثم أعد اختبار الاتصال.

العَرَضنقطة بداية الفحص
الراوتر يصل إلى الفرع لكن PC-A لا يصلقارن عنوان الحاسب وقناعه وبوابته بالخطة
الوصلة بين الراوترين لا تعملافحص الكابل والواجهة باستخدام show ip interface brief
البوابة المحلية تستجيب والوجهة البعيدة لا تستجيبافحص جدول التوجيه ومسار العودة
واجهة LAN تعمل لكن الحاسب لا يصل لبوابتهافحص منفذ السويتش والعنوان والقناع
