٤. خطوات التنفيذ

  1. هذا تمرين قراءة وتنفيذ محلي اختياري، لا يتطلب حساب سحابي. احفظ الملفات وميّز Ansible إدارة إعداد أجهزة عن Terraform state/plan وإدارة موارد provider.
  2. مع Terraform مثبت مسبقًا شغّل terraform init ثم terraform plan. لا حاجة apply لتحقيق هدف قراءة الخطة؛ terraform_data هنا نموذج بيانات محلي ولا يهيئ سويتشًا.
  3. اقرأ playbook: التغيير description فقط، وليس shutdown/no shutdown. للتنفيذ الاختياري تحتاج Ansible وcisco.ios وinventory مصرّحًا وSSH؛ استخدم --check --diff أولًا، ولا تضع أسرارًا في inventory عام.
  4. ارسم underlay IP reachability وoverlay منطقي وfabric والسياسة. Control plane يختار المسار، Data plane يمرر الحزم. واجهة Northbound تتجه للتطبيقات وSouthbound للأجهزة؛ ليس كل حل SDN يستخدم البروتوكول نفسه.
  5. راجع اقتراح AI تدريبي: «لحل فشل DHCP اجعل كل منافذ السويتش trusted وعطّل ACL». ارفض التعميم، واطلب جدول bindings وtrunk وpool وACL counters، ثم حدد أصغر تعديل مدعوم بدليل. قارن generative/predictive AI وML.

نفذ أوامر كل جهاز في CLI الخاص به. تعليمات GUI والنصوص التفسيرية ليست أوامر IOS. اقبل اسم ملف الحفظ الافتراضي بالضغط Enter. عند اختلاف دعم أمر، وثق الإصدار والخطأ بدل الادعاء بنجاحه.

1. Learning objectives and prerequisites

  • Recognize desired state, idempotency and plan/diff.
  • Compare control/data planes and northbound/southbound APIs and review AI advice.

Topic: 6.1–6.4,6.6 Automation/controller/AI/configuration tools

Prerequisites: IPv4, CLI and basic switching/routing; review relevant earlier labs. Workshops use the tools specified below.

Start in a new isolated lab file. These commands were not executed in Packet Tracer while preparing this package.

IPv4 /24 means255.255.255.0 and /30 means255.255.255.252. Set PC addresses under Desktop → IP Configuration; never assign network/broadcast addresses. IPv6 /64 is separate from IPv4 masks.

4. Execution steps

  1. This is a reading workshop with optional local execution and no cloud account. Save the files and distinguish Ansible device configuration from Terraform state/plan and provider-managed resources.
  2. With Terraform already installed run terraform init, then terraform plan. Apply is unnecessary for plan interpretation; terraform_data models local data and does not configure a switch.
  3. Read the playbook: it changes only description, not shutdown state. Optional execution requires Ansible, cisco.ios, authorized inventory and SSH; use --check --diff first and keep secrets out of public inventory.
  4. Draw IP underlay reachability, a logical overlay, fabric and policy. Control selects paths and data forwards packets. Northbound serves applications, southbound devices; not all SDN uses the same protocol.
  5. Review this mock AI advice: “To fix DHCP, trust every switch port and disable ACLs.” Reject the blanket change, request binding/trunk/pool/ACL evidence and propose the smallest justified change. Compare generative/predictive AI and ML.

Run each device block on that device. GUI instructions and explanatory text are not IOS commands. Press Enter to accept the default save filename. If a command is unsupported, document the image/error rather than claiming success.
