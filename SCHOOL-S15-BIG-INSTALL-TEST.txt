SCHOOL S15 BIG — CORE SECURITY + PERMISSIONS CLEANUP
====================================================

الهدف:
------
تحويل ما تم بناؤه حتى S14 إلى قاعدة أمن وصلاحيات موحدة قبل إضافة وظائف جديدة.
هذا Sprint تجميعي/تأسيسي وليس Hotfix.

ما الذي يتم توحيده؟
-------------------
1) أدوار المدرسة:
   - school_admin
   - teacher
   - parent
   - student
   - employee

2) Multi-role:
   نفس الحساب يستطيع أن يكون Parent + Teacher أو أي أدوار مختلفة.
   هذا ليس Conflict.

3) Teacher Authorization:
   الدالة الأساسية الوحيدة:
   school_teacher_can_manage_class(class_section_id, subject_id)

   والاسم:
   school_teacher_can_manage(...)
   يبقى اسمًا رسميًا متوافقًا مع الأكواد القديمة، لكنه يستدعي نفس الدالة الأساسية.
   لا توجد قاعدتا صلاحيات مختلفتان.

4) Student Access:
   school_can_access_student(student_id)
   school_can_access_enrollment(enrollment_id)

   الوصول مسموح فقط لـ:
   - School Admin
   - الطالب نفسه
   - ولي أمر مرتبط
   - معلم لديه Assignment للفصل

5) Auto Auth Linking:
   Student / Parent / Teacher / Employee
   Email -> auth.users -> auth_user_id
   تلقائيًا عند INSERT أو تغيير Email.

6) Role-aware conflict detection:
   Parent + Teacher لن يعتبر Conflict.
   Conflict فقط إذا نفس Auth مربوط بأكثر من سجل من نفس النوع.

7) Central Security Health:
   school_security_health()
   يفحص:
   - Missing core functions
   - Same-role conflicts
   - Teachers unlinked
   - Parents unlinked
   - Students without login
   - Employees unlinked
   - Teachers without assignments
   - Active enrollments without class
   - School tables with RLS disabled

8) Admin Security Page:
   /school/admin/security

   تعرض نتيجة الفحص المركزي.
   الطلاب بدون Login يظهرون كمعلومة، وليس بالضرورة خطأ.
